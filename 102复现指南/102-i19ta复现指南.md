# 102：I-19 TA 从 I-13 开始的复现指南

> 适用范围：队友已经完成 I-13，本指南只覆盖 I-13 之后的成功版 I-19 主线。仓库中没有名为 `i19ta` 的符号；本文将它解释为 **I-19 最终成功的 TA/复现任务**，即 `i19_world_userres_retkl_r16_ep1_i13retain_v1`（I-13 式 retention 版本），而不是已经证伪的早期 A1/A2。
>
> 推荐工作目录：`llmrec_2026-main` 仓库根目录。以下命令均从这里执行。

## 0. 一句话结论

成功方案是在已复现的 I-13 rank-80 adapter 上新建 rank-16 world residual：

- 1,573 条 clean world 数据：`gold CE + 0.05 × KL(parent)`；
- 1,573 条八业务域保持数据：`CE=0 + 2.0 × KL(parent)`；
- 训练 1 epoch（787 steps），再以 `residual-scale=0.875` 与 I-13 精确拼接为 rank-96 adapter。

历史实测：训练 loss 约 `0.5217204`；线上单次总分 `1.0253`。该分数只能作为复现参考，不能保证因硬件、软件版本及平台波动而逐位一致。

## 1. 为什么不要复现早期 I-19 A1/A2

- **A1** 只在 world 行上计算 `CE + 0.5 KL`，没有在真实业务输入上做 retention；线上 world 上升，但 material、video 和总分明显下降，属于容量挤占。
- **A2 OPD** 使用 293 条 student thinking rollout，离线准确率和 parent 保持均不如 A1，已经关闭。
- **本指南版本** 按 I-13 stage-2 的思想加入等量业务域 KL-only 保持数据，是当前应复现的主线。

所以，本包刻意不携带 `train_i19_world_retkl.py`、`train_i19_world_opd.py` 和 OPD 数据构建脚本，避免误跑废弃路线。

## 2. 前置环境

### 2.1 已完成的 I-13

必须准备以下具体 parent，而不只是“某个 I-13”同配方模型：

```text
checkpoints/i13_repro_combined_r80_s875/
├── adapter_config.json
└── adapter_model.safetensors
```

它应是 I-13 rank-64 parent 与 rank-16 user residual 按 `0.875` 拼成的 rank-80 adapter。曾经用队友另一份 `i13_origin_r80_s800` 做过消融，I-19 三个 scale 的线上结果全部更差，因此默认不要替换 parent。若必须换 parent，要视为新实验，重新扫描 scale 并重新评测。

### 2.2 Base model

默认路径：

```text
models/OneReason-0.8B-pretrain-competition/
```

训练配置和 tokenizer 自测都使用此目录。模型应与 I-13 使用的 OneReason-0.8B base 完全一致。

### 2.3 软件和硬件

复用 I-13 已验证环境即可，核心依赖为：

- Python、PyTorch（CUDA + bf16）；
- LLaMA-Factory（能导入 `llamafactory.train.sft`）；
- Transformers、PEFT、Safetensors；
- FlashAttention 2（配置为 `flash_attn: fa2`）；
- 单卡可运行，历史训练约 16 分钟；实际显存和时间取决于 GPU 与依赖版本。

配置默认开启 W&B：`report_to: wandb`。无 W&B 环境时可登录/设置离线模式，或将 YAML 的 `report_to` 改为 `none`；这不改变训练目标。

## 5. 完整复现步骤

### Step 1：构建 world/retention 混合数据

```bash
bash /path/to/102复现指南/复现脚本.sh "$PWD" build-data
```

等价核心命令：

```bash
python scripts/data/build_world_residual_retention_v1.py \
  --world-source assets/derived/releases/i19_frinkleko_world_1578/data_i19_frinkleko_world_1578_clean.jsonl \
  --retain-source assets/derived/releases/e3_userres_r80_retkl_v3_s875/data_seed_teacher_v1.jsonl \
  --out assets/derived/releases/i19_userres_retention_v1/data_world_residual_retention_v1.jsonl \
  --audit assets/derived/releases/i19_userres_retention_v1/manifest.json \
  --seed 19260821
```

检查：输出应为 3,146 行，manifest 应记录 world/retention 各 1,573 行及八桶分配。

### Step 2：运行代码自测

```bash
bash /path/to/102复现指南/复现脚本.sh "$PWD" self-test
```

它验证：

- 分块 CE/KL 与直接计算一致；
- terminal token 权重与梯度正常；
- 真实 tokenizer 下两个路由前缀可正确识别；
- 两个 LoRA 的 rank 拼接在数学上严格等价于加法 delta。

自测必须通过后再训练。

### Step 3：训练 rank-16 world residual

```bash
GPU=0 bash /path/to/102复现指南/复现脚本.sh "$PWD" train
```

关键超参：

| 项目 | 值 |
|---|---|
| parent | `i13_repro_combined_r80_s875`（rank 80） |
| 新 adapter | LoRA rank 16 / alpha 16 / dropout 0.05 / target all |
| learning rate | `5e-5` |
| epoch | 1 |
| batch | per-device 1，gradient accumulation 4 |
| scheduler | cosine，warmup ratio 0.03 |
| cutoff | 4096 |
| packing | false（必须） |
| bf16 | true |
| seed | 19260821 |
| world parent KL | 0.05 |
| retention KL | 2.0 |
| terminal multiplier | 2.0 |
| logit chunk | 16 |

损失语义：

```text
world:      weighted_gold_CE + 0.05 * forward_KL(parent || policy)
retention:  0 * CE              + 2.00 * forward_KL(parent || policy)
```

实现上，LLaMA-Factory 把 I-13 parent 合入 frozen base，并创建新的 rank-16 adapter。临时 `disable_adapter()` 得到精确 parent logits，所以不需要在显存中加载第二套完整模型。

预期：

- 3,146 行、有效 batch 4，约 787 optimizer steps；
- 日志中 `route=world` 与 `route=retention` 都应持续出现；
- retention 行必须显示 `ce=0.000000`；
- 输出目录：`checkpoints/i19_world_userres_retkl_r16_ep1_i13retain_v1/`；
- 历史参考 `train_loss=0.5217204`，仅用于发现量级异常。

若第一批就提示无法识别 route，通常是 tokenizer/base 不一致、数据未由本包 builder 生成，或 LLaMA-Factory 模板版本不兼容。不要绕过路由检查。

### Step 4：拼接为 rank-96 最终 adapter

```bash
bash /path/to/102复现指南/复现脚本.sh "$PWD" combine
```

等价核心命令：

```bash
python scripts/train/combine_lora_adapters.py \
  checkpoints/i13_repro_combined_r80_s875 \
  checkpoints/i19_world_userres_retkl_r16_ep1_i13retain_v1 \
  checkpoints/i19_world_userres_retkl_r16_ep1_i13retain_v1_combined_r96 \
  --residual-scale 0.875 \
  --audit checkpoints/i19_world_userres_retkl_r16_ep1_i13retain_v1_combined_r96/.audit.json
```

数学恒等式：

```text
delta_final = delta_i13_parent + 0.875 * delta_i19_residual
```

最终应为 rank 96、alpha 96，目标模块与 parent/residual 完全一致。用于提交的核心文件是：

```text
adapter_config.json
adapter_model.safetensors
```

## 6. 可选：本地多 scale Pareto 审计

```bash
GPU=0 bash /path/to/102复现指南/复现脚本.sh "$PWD" audit
```

扫描 `0,0.25,0.5,0.75,0.8,0.875,0.9,1.0`。指标含义：

- world CE delta：从训练过的 world 行抽样，只证明 residual 学到了训练信号，不是无污染泛化评测；
- retention held-out KL / top-1 agreement：从八业务桶排除训练所选行后分层抽样，衡量相对 parent 的漂移；
- 它是机制和 Pareto 审计，**不是线上分数预测器**。

历史关键点：`0.875` 的 world CE 收益已接近 `1.0` 饱和点，但平均保持 KL 约低 9%，因此选 `0.875`。线上 video 指标曾出现非单调噪声，本地 KL 未能预测该现象。

## 7. 评测与数据防火墙

1. 不要用旧 `ceval_clean` 证明泛化：I-19 world 训练数据有 C-Eval 血统。
2. `assets/evaluation/ceval_world_i19_posttrain_clean/` 仅 24 题，方差很大，只能做最终候选冒烟，不能按逐题结果挑 checkpoint。
3. 任何线上可见题、输出和评测日志均不得回灌训练、蒸馏或筛选。
4. 最终判断应比较同一个 I-13 parent：world 是否提升、其余能力和总分是否保持；不要混用集群原始 I-13 与本地复现 I-13 的分数。

| I-13 本地复现 parent | 0.9867 | 0.2453 | 0.1207 | 0.0386 | 0.0864 | 0.1190 | 0.1302 | 0.1071 | 0.1394 |

## 8. 常见问题

### 数据 hash 不一致

优先核对文件是否为 `_clean` 1,573 行版、I-13 数据是否为 32,644 行、是否擅自重新排序/格式化。builder 输出 manifest 会记录上游和输出 SHA256。

### 显存不足

先保持 `per_device_train_batch_size=1` 不变；自定义 loss 明确要求 batch size 1。可减小 `WORLDRES_LOGIT_CHUNK`，代价是变慢。不要开启 packing。

### 从 checkpoint 续训

成功版只有 1 epoch。若中断，按当前 LLaMA-Factory 的 resume 机制谨慎恢复并保留同一配置；不要把某个中间 checkpoint 误当作 residual 根目录参与拼接。

### 能否直接换成另一个 I-13 adapter

不建议。residual 是围绕具体 parent 的函数分布训练的。换 parent 后，即便 adapter rank/alpha 一样，也需要重新训练、审计和评测；历史换 parent 消融已经负向。

### `0.875` 是训练系数吗

不是。训练 rank-16 residual 时它的 LoRA alpha/rank 是 1；`0.875` 是训练完成后与 I-13 parent 拼接时对 residual delta 的缩放系数。
