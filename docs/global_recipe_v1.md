# 全局配方设计 v1 —— 按官方《赛题解析》重构整张 SFT 数据表(2026-07-07)

> **设计裁决(用户 07-07)**:0.8B 容量零和,单项加包必在别处交税(v2/tokengeo/pstack 三次线上验尸)。
> 停止"底座+骑手"式补丁,**把整份数据当一个容量预算一次性分配**,全面对标官方 PPT(docs/reference/赛题解析_官方.pdf)。
> 目标:峰值总和≈1.01 不再散落在七份权重里,一份权重同时持有。

## 一、设计原则

1. **容量=预算**:按分值权重分配容量——懂推荐×4 > 懂用户×2 > 物料×1=世界×1。数据占比即容量分配。
2. **官方产线优先**:每个数据块必须能指到 PPT 页码/FAQ 条目,不自创形态(tokengeo 的教训)。
3. **总量不膨胀**:全表 ~33k 条(种子同级)。加块必减块,不做纯追加。
4. **CoT 压缩**(PPT 沙龙页原话"需要压缩:降噪、找到最重要的部分"):新写 CoT 一律 100-200 字。
5. **毒物红线**(README 八条):不重复上采样、不进 HF 墙外物料、不全域剥 CoT、不截断答案、复制类训练必配 MC 锚。

## 四、CoT 规范(新写的一律遵守)

- **I-A-D 三段压缩体**(replacing 种子"兴趣归纳→行为模式→预测总结"平铺三段):
  归纳 1 句(核心兴趣点)→ 溯因 1-2 句(兴趣背后的原因,主导段)→ 演绎 1-2 句(由因推未来兴趣,收束到物料方向)。100-200 字,不复述历史,不写"我认为/让我们"。
- **UnCoT**:`<think>\n\n</think>\n`+直接答案(种子惯例逐字)。
- think/nothink 模板尾缀与内容严格配对(种子惯例);答案 itemic 三元组必须完整(T2 红线)。

## 六、预登记(区间,非承诺)

各子项若同时守住已观测水平:mat 7 题+action 0.08+topic 0.05(新)+video 8-9+prod 37-40+ad 99-103+live 118-122+world 0.145 ⇒ **上行 0.96-0.98;中位预期 0.94-0.95**。
判据:①总分之外逐项过"是否守住 riders 面板"清单,任何块塌方即归因到对应数据块;②topic≥0.048 判 U3 生死;③video/ad 按重标读数。
死法(红队):①I-A-D CoT 重写坏了 rec 直出通路(对冲:30% 直出样本保通路);②teacher 风格与官方 API 风格差(对冲:few-shot 全用官方原文锚);③G 通用块挤占(对冲:占比压 9%,低于警戒线)。
