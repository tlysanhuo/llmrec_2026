### 1.3 回答"坍缩是否解释回退":**否,坍缩不是 v4 回退的主因**

- s_a 坍缩(≤5)v4 并不比 v1/v3 更严重:v1 1/5、v3 **3/5**、v4 2/5。**v3 坍缩最狠却拿 0.184 最高分**,
  v4 反而更发散(星座题 6→12 s_a、儿童题 4→11 s_a)却掉到 0.153。
- 真正的差异是 **beam 概率质量从"对的头部"漂移走了**:v3→v4 全部 5 题 top1 都变了;
  v3 主桶的质量在 v4 大幅流失(38→10、13→3 条)。v1/v3(同分 0.184)在共同题上 top1 一致(摄影题),v4 变了。
- 解释:多 epoch(3ep)训练让 desc→s_a 的条件分布整体偏移/变平,首 token 押注从原来能命中 gold 的
  s_a 挪到了别处;beam64 里"距离 top1 的多样性"没少,但**s_a 命中率**掉了(grounding 是 pass@64 型,
  s_a 错则整条错;s_a 只有 ~11-15 个 distinct,远小于 64,浪费大量候选在 s_c 枚举上)。
- 与实验记录一致:v4 物料 0.1533 恰好**跌回 pretrain 锚点 0.1533**——SFT 在该维度的增益被完全抹掉。

## 5. 结论(按行动价值排序)

1. **grounding 回退的病因是"s_a 首 token 概率质量漂移",不是多样性坍缩**——v3 坍缩最重(3/5 题
   s_a≤5、主桶 78%)却保住 0.184,v4 更发散反而跌到 pretrain 锚点 0.1533;v3→v4 五对同题 top1 全变、
   v3 主桶质量流失(38→10 条)。同时"二手车"型坍缩题里 83% 候选在枚举 s_c、distinct s_a 仅 3,
   beam64 的容量被 s_c 浪费。**两点都指向同一个处方:itemic 加权/首 token(s_a)加权训练(recipe2)
   ——既要把 s_a 的条件分布钉回 gold,也要让 beam 在 s_a 层展开**。
2. **action_select 的复读截断是懂用户子项最大的残留损失**:v4 可见样本 4/5 复读到 4096 上限、
   JSON 合法率 1/5,且复读 token 多为历史外幻觉;F1 翻倍全靠非复读样本"选得更全"(10 条 vs 3~5 条)。
   在 recipe2 之外,针对该任务加 EOS/重复抑制训练(或输出去重后重训)预计还有一截独立收益
   (懂用户权重×2,值得单独做数据)。
3. **rec 域的 beam"该发散处发散、该收敛处收敛"**:ad +43% 伴随 s_a 多样性↑、抄历史率 0.95→0.88;
   prod 微跌伴随抄历史率 0.80→0.92、模态桶占比 0.14→0.22。若做 rec 向数据/加权,方向不是无脑
   提多样性,而是**降低对"历史 s_a 复制"的依赖、提升域内头部(s_a)判别**——video 域多样性降了分数
   却不动,说明 s_a 押对比铺开更重要,同样佐证 s_a/itemic 加权路线。
