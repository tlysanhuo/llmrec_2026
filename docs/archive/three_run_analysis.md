# 三次实验演进分析（v1 → v2 → v3）

> **诚实前置声明（必读）**：本报告赖以分析的 8 个任务的逐样本日志(`/root/baseline_repro/log3way/*`)**几乎全部是坏的**。除 `challenge_common_sense` 外，7 个任务的 v1/v2/v3 三份 `.txt` 文件**去掉第 3 行时间戳后逐字节相同**（多任务 md5 一致，如 topic_gen 三版均为 `f256084f2ead54de4c26edf844fc47aa`），且都在**输入 prompt 回显中途被硬截断**，**完全没有落盘模型生成的 semantic ID / JSON 数组 / beam 候选 / target**。因此本报告中所有"模型行为演进"的判断，**只有 common_sense 是样本级证据，其余 7 项都是从分项分数 + 机制推断得出的相关性结论，不能坐实因果**。凡属推断处均已标注。这本身就是第一个、也是最重要的发现。

---

## (1) 总述：分数轨迹 0.810 → 0.8092 → 0.8198 背后到底发生了什么

三次实验对应三个数据配方：
- **v1 = baseline_sft**（基线）
- **v2 = run_a_r2**（在 v1 上加"懂用户 R2"数据）
- **v3 = run_c_material**（在 v2 基础上加"懂物料 desc2token 1万条"数据）

从子项分数拆解，真实的行为轨迹是一条"**先负迁移、后靠正迁移反超**"的曲线，而非平滑上升：

| 子项 | v1 | v2 | v3 | v1→v2 | v2→v3 |
|---|---|---|---|---|---|
| 世界(common_sense) | 0.1375 | 0.1294 | 0.1346 | **−0.0081** | +0.0052 |
| 用户 topic_gen | 0.0392 | 0.0430 | 0.0407 | +0.0038 | −0.0023 |
| 物料(itemic) | 0.1840 | 0.1840 | 0.1840 | **0（冻结）** | **0（冻结）** |
| 推荐 ad | 0.0672 | 0.0480 | 0.0768 | **−0.0192** | **+0.0288** |
| 推荐 live | 0.1054 | 0.1054 | 0.1020 | 0 | −0.0034 |
| 推荐 product | 0.1316 | 0.1274 | 0.1274 | −0.0042 | 0 |
| 推荐 video | 0.1089 | 0.1053 | 0.1098 | −0.0036 | +0.0045 |
| **总分** | **0.810** | **0.8092** | **0.8198** | −0.0008 | **+0.0106** |

**行为叙事（三句话）：**
1. **v2 加"懂用户"数据 = 近乎全域负迁移**。除 topic_gen（+0.0038，本就该受益的同域子项）外，世界、ad、product、video 全部下滑，ad 一项就掉 0.0192。这批数据挤占/扰动了"生成类 + 单选类"的能力，总分不升反微降。
2. **v3 加"懂物料 desc2token" = 精准正迁移，且是跨维的**。它没有回补自己名义上的目标（物料分**纹丝不动 0.1840**），却把 ad 从 0.0480 拉到 0.0768（**反超 v1**）、video 拉到全场最高 0.1098、世界从 0.1294 回补到 0.1346。总分靠这几项的合力冲到 0.8198。
3. **有两个子项被永久卡死**：物料(itemic) 三版恒等 0.1840，是唯一对两次数据改动"零响应"的项；live 则对两批数据都无正响应甚至下滑。这两项是当前配方碰不动的硬骨头。

**一句话总结**：v3 最高，不是因为它"学会了物料"，而是因为**物料 token 对齐这批数据泛化到了"生成 semantic ID"这一类任务（ad/video）上，顺带把 v2 造成的负迁移坑填平并反超**。

## (2) 逐维度演进 + 分数解释 + 核心问题 + 提分抓手

### 世界 / 常识（challenge_common_sense，单选 Accuracy，807 题）
- **行为演进（样本级可证）**：这是**唯一有真实输出**的任务。三版输出**逐字节相同**（S0=D、S1=D，纯单字母格式干净）。S0"中国最大淡水湖"正解 A、三版都答 D（模型常识缺陷），S1 奶酪棒 D 对。
- **分数解释**：v1=0.1375 → v2=0.1294 → v3=0.1346。展示的 2 题三版完全一致，格式已满，**分数波动全部来自 807 全集中未展示题目的正误翻转**。v2 掉 0.0081 是"懂用户"数据对常识能力的负迁移，v3 靠物料数据回补一部分。
- **核心问题**：格式无提分空间；瓶颈是**常识正确率本身**；加"懂用户"数据会拖累常识。
- **提分抓手**：① 混训做能力隔离，保住 v1 的常识基线不被"懂用户"数据侵蚀；② 补中文百科常识 SFT（提正确率而非格式）；③ dump 全 807 题的三版正误对比，找出翻转集，精准调配比。

### 懂用户（topic_gen + action_select，sample 出 JSON 数组，F1 打分）
- **行为演进**：**无法观测**——topic_gen 三版逐字节相同、在 Sample 1 的 `[商品-购买] <|prod_begin|><` 处截断，无任何 JSON 数组输出；action_select 样本同样被截断无输出。
- **分数解释**：topic_gen v1=0.0392 → v2=**0.0430** → v3=0.0407；action_select v2=0.0667。**v2 加"懂 R2 用户"数据是唯一让 topic_gen 上升的改动**（同域正迁移），而 v3 加物料数据反而把它稀释回 0.0407（物料对话题生成无正迁移）。
- **核心问题**：F1 停在 0.039~0.043 的**地板区**，说明"从交互历史归纳兴趣话题 + 对齐 JSON 数组 schema"这个能力**基本没学会**；叠加日志采集失效，无法做行为归因。
- **提分抓手**：① 补"懂用户/话题生成"定向 SFT（对齐 JSON schema + 兴趣归纳），**不要用物料数据填这个坑**；② 修日志，确认是 EOS 收尾还是被截断，怀疑存在复读退化，可加 repetition_penalty 治理。

### 懂物料（challenge_itemic_pattern_grounding，视频描述→semantic ID，Pass@64）
- **行为演进（样本级部分可证，此任务日志较完整）**：格式 100% 规范（574 样本全部输出 `<|video_begin|><s_a><s_b><s_c>` 三段式，无复读/幻觉/格式错）。三版本质是**同一份 beam 池的重排**：二手车样本候选 triple 集重合 85–91%（v1∩v2=29/32），a 段恒被 `s_a_5254` 主导（29~30/32 beam），b 段集中在 6442/3417；三版唯一差异是 top beam 的 c-token 在同一候选池内洗牌（5563/6067/2370），属噪声级抖动。
- **分数解释**：v1=v2=v3=**0.1840 逐位相同**，与"仅重排、候选集与主导 token 不变"完全吻合——排序洗牌不改变 Pass@64 命中集合。**这是唯一对"加数据"零响应的子项，是明确的"投入未产出"信号**（desc2token 1 万条没有兑现为物料分提升）。
- **核心问题**：物料分被**冻结**。两个可能原因：① desc2token 的 token 空间/格式与评测 beam 解码空间不对齐，模型没学到新的 description→semantic ID 映射；② **0.1840 可能是结构性上限**——ground-truth semantic ID 不在模型 codebook/词表覆盖内，Pass@64 命中率被 codebook 本身卡死。
- **提分抓手**：① 校验 desc2token 的 token 取值域是否与评测 codebook **严格同源同格式**；② 确认 ground-truth ID 是否落在模型可生成 beam 空间内，若 0.1840 是 codebook 天花板，应**先扩/对齐 codebook 而非加 SFT**；③ 提 beam 多样性/去重后取更多 unique triple；④ **战略上转低优先级止损**，算力投给有响应的维度。

### 懂推荐（ad / live / product / video，两阶段：thinking + beam×3token 生成 semantic ID，Pass@64）
- **行为演进**：**四个子任务全部无法观测**——v1/v2/v3 三版仅时间戳不同、逐字节相同、在输入回显中途截断、零 Output 段。这是**系统性日志采集/截断问题**（对照 common_sense 末尾有真实 `Output[0]: D`，证明落盘管线本身能捕获输出，是推荐类 beam 路径被超长 prompt 回显挤爆/未落盘）。仅有的单版本完整日志 `eval_log_chunks/7_challenge_recommendation_product.txt` 揭示真实行为：每样本 64 候选中 Output[0..31] 带几乎逐字复读的长 `<think>` 模板，Output[32..63] 退化为裸 ID 无思维链；候选 s_a 前缀高度集中（526/3866/4887/4436），**beam 只在 s_b/s_c 微扰、多样性低**。
- **分数解释（只能靠分数+机制推断）**：
  - **ad**：0.0672 → 0.0480 → 0.0768。波动最大。"懂用户"是强负迁移，"懂物料"是强正迁移（+0.0096 vs v1，全场最高）。
  - **video**：0.1089 → 0.1053 → 0.1098。同 ad 形态，v3 三版最高。
  - **product**：0.1316 → 0.1274 → 0.1274。v2 掉后 v3 **未回升**——物料数据对 product 无正迁移。
  - **live**：0.1054 → 0.1054 → 0.1020。对两批数据无正响应，v3 还掉 0.0034，是唯一 v3 下滑的推荐子项。
- **核心问题**：① 阻断性——日志无输出，无法做命中/幻觉/答案分布分析；② 建模——beam 多样性过低（s_a 前缀集中）压低 Pass@64；③ 一半候选退化为无思维链裸 ID；④ ad 绝对分仅 0.07 量级、天花板高，是最高性价比单项；live/product 对现有两类数据中性偏负迁移。
- **提分抓手**：① **先修 dump**（落盘每样本 64 条 beam 输出 + target + 命中），复用 common_sense 的 `Output[N]:` 落盘逻辑到 beam 路径，去掉超长 prompt 回显截断；② **放量/提纯"懂物料"desc2token 覆盖 ad 域**（ad/video 是强正迁移受益者）；③ 让"懂用户"数据与推荐生成**解耦**（分阶段训练/降权），避免对 ad/product 的负迁移；④ 提 beam 多样性（diverse/group beam、增大 beam_width、s_a 首 token 加探索）；⑤ live 需专门补"跨域行为序列→目标主播 semantic ID"的对齐监督，现有数据都不教这个映射；⑥ 缩短冗长复读的 `<think>` 模板，把算力从思维链转到更多有效候选。

## (3) ★关键洞察：哪些改动有效 / 无效 / 有害，为什么

### 有害的改动：v2 加"懂用户 R2"数据 → 近乎全域负迁移
- **证据**：v2 相对 v1，世界 −0.0081、ad −0.0192、product −0.0042、video −0.0036，只有同域的 topic_gen +0.0038。总分从 0.810 微降到 0.8092。
- **机制推断**：懂用户数据教的是"输出 JSON 风格/兴趣归纳"，与"生成 semantic ID"和"单选常识"是**竞争性能力**。它挤占了模型在语义 ID 分布对齐上的容量，或让模型在推荐/常识时偏向 JSON 风格输出。**这是一次典型的"为了拉起一个弱小子项(topic_gen 0.039)，赔掉了多个强子项"的亏本买卖**。

### 无效的改动：v3 的 desc2token 对"物料任务本身"零产出
- **证据**：物料分三版恒 0.1840，样本层面三版仅 beam 重排、候选池/主导 token/格式均不变。
- **机制推断**：token 空间错位，或 0.1840 已是 codebook 结构性天花板。**加了 1 万条物料数据，物料分一分没涨**——这是最值得警惕的"投入未产出"信号，说明"喂同类数据"这条路对该任务已失效。

### 有效的改动：v3 的 desc2token 的**跨维正迁移**——这才是 v3 夺冠的真正原因
- **证据**：ad 0.0480→0.0768（反超 v1）、video 0.1053→0.1098（三版最高）、世界 0.1294→0.1346（回补）。物料本身不动，但总分因这几项冲到 0.8198。
- **"加物料却是懂用户+推荐涨"的跨维效应到底怎么回事？**
  - **需先澄清**：本次数据里**真正涨的是 ad/video/世界，不是"懂用户"**（topic_gen 反而从 0.0430 掉到 0.0407，懂用户维度被物料数据稀释）。所以准确的说法是"**加物料数据，物料不涨、但推荐生成类(ad/video)涨、世界回补**"。
  - **机制**：ad/video 的本质任务是**生成 `<s_a><s_b><s_c>` 三段语义 ID**。desc2token(description→semantic token) 数据**直接强化了模型对这套三段 token 的表征与对齐能力**。这种能力不体现在物料任务上（物料被 codebook/重排卡死，没有释放空间），却**泛化**到了同样依赖三段 token 生成的 ad/video 上——它们对齐更好、beam 命中更多，于是分数上升。
  - **另一半功劳是"填坑"**：v3 是在 v2 基础上叠加的，v2 把 ad 砸到 0.0480、世界砸到 0.1294。物料数据**修复了 v2 造成的负迁移并反超**。所以 v3 的 +0.0106 = 一部分是真实正迁移 + 一部分是修 v2 的坑。
  - **一个关键佐证**：物料分恒 0.1840 说明 **desc2token 没有过拟合到物料评测本身**，它的收益完全通过泛化到 ad 生成体现——这与"抓手 = 放量懂物料数据"的判断一致，且这种收益比"死磕物料分"更健康。

## (4) 对追赶榜首（0.8784，差 0.0586）的启示：最大未开发空间在哪

**差距 0.0586 相当可观，但几乎全部集中在"低分、高天花板、且已被证明对数据有响应"的推荐生成类子项上。** 按机会大小排序：

1. **最大空间 = 日志采集本身（元问题）**。8 个任务里 7 个的三版对比日志是废的，我们**至今没能对任何生成类任务做过一次真正的逐样本行为归因**。修好 dump 是解锁后续所有优化的前提，零算力成本、最高优先级。**在拿到真实输出前，我们其实是"闭着眼调数据配比"**。

2. **推荐生成类子项（ad/video/product/live）绝对分都在 0.05–0.13**，远未饱和。ad 只有 0.0768、live 0.1020，天花板很高。已证实"懂物料 desc2token"对 ad/video 是强正迁移——**放量+提纯这批数据、扩大到 ad/live 域**，是性价比最高的方向。

3. **两个被卡死的硬骨头（结构性空间）**：
   - **物料 0.1840 疑似 codebook 天花板**——若属实，扩/对齐 codebook 可能一次性打开一个 0.18 量级子项的上限，这是**单点收益最大的赌注**，但需先验证是不是天花板。
   - **live** 需要"跨域行为→主播 semantic ID"的**新监督信号**，现有数据都不教这个映射。

4. **懂用户维度（topic_gen 0.039 地板区）** 是被彻底忽视的洼地，但要用**定向 SFT** 去做，且必须与推荐生成能力**解耦训练**，否则重蹈 v2 全域负迁移覆辙。

**最诚实的结论**：我们最大的未开发空间不是"再加一批数据",而是**(a) 修好评测日志、真正看见模型在生成什么；(b) 验证物料 0.1840 是否为 codebook 天花板；(c) 学会"能力隔离/分阶段训练"以吃到正迁移(物料→ad)又不吃负迁移(用户→全域)**。这三件事做不到，0.058 的差距很难靠继续叠数据配方填平。
