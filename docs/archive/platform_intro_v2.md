# 万擎平台介绍 (官方文档更新 2026-07-02 14:33)

> 官方平台文档第二次更新。本文件记录全文要点 + 对我方的关键含义。原始首版见早期记忆。

## 平台四能力
- **数据集**:上传 JSONL/CSV/XLSX,自动校验;多版本管理(对比不同配比);内置竞赛专项数据集可直接调用。
- **模型训练**:两种方式——①**模型定制-精调(推荐)**:平台全托管,LoRA/全参,可配迭代轮次/学习率/批大小,**可拆验证集**,预置 train_loss/eval_loss 曲线,**自定义 loss 函数**(如商品 token 加权、难样本聚焦);②**模型研发-开发机**:云端 VSCode/Terminal,预置 PyTorch/ms-swift,挂共享存储。
- **模型仓库**:精调自动归档;开发机/线下训练手动上传。
- **竞赛评测**:一键跑 OneRec Benchmark → 四维度得分;**每日限 3 次**,失败不消耗。

## 三种参赛路径
1. 平台精调(托管,专注数据+调参,一键连评测,**框架不可改但可改主要训练参数+自定义loss监控**)
2. 开发机(自定义训练代码/loss/数据逻辑,训完手动上传)
3. 本地/其他平台训练 → 上传模型评测(**我们走这条**)

## 关键规则(FAQ,与我方直接相关)
- **Q2**:初赛只能基于 OneReason-0.8B 迭代,评测**严格校验 config 与 baseline 一致**。
- **Q3**:baseline **不提供 RL 代码**,RL 自行实现。
- **Q6**:可自定义 SFT 配比、自建 RL;**不可改模型结构/预定义参数/评估设置**。
- **Q7**:数据高度灵活(可引外部通识、造定制推荐数据);**复现阶段须交构造数据集+训练脚本,官方续训复现,误差内即可**。
- **Q8**:线下训练**建议 Transformers v5.3.0**;全参传 model.safetensors(+分片 index)。
- **Q10**:允许蒸馏;不鼓励模型融合;复赛须交**单模型**方案过审。
- **★Q12(重要)**:pre-train 模型基线 **总分 0.6655**(物料0.1533 / 用户0.0000,0.0055 / 推荐0.0864,0.0544,0.1372,0.0900 / 世界0.1387)。vLLM 波动 ~1%。
- **★★Q13(新,关键)**:各子任务得分**是乘过权重后的**——"各任务难度不同,设了不同权重,让各子任务量纲尽量一致"。→ **我们看到的 8 个分项已是加权值,总分=8项加权和。**
- **★Q14(新)**:初赛平台**不保证给训练资源**(资源紧张),要队伍**自备算力** + 平台每周限量资源(3B+);复赛才给每队资源;**不提供免费 API 做数据构建**。

## 对我方的核心含义
1. **Q14 印证竞争格局**:头部"用自己算力"(克西评论)= 官方明说初赛靠自备算力。**我们有 8×H100,算力不是瓶颈,是没把训练做够。**
2. **Q13 改变分项解读**:8 个分项是加权后的值,不是原始指标。之前"总分=8项相加"仍成立(它们已是加权分)。但"懂推荐4项权重最大"的推断要谨慎——权重已隐含在分值里,难度归一化过。
3. **平台自带 eval_loss + 自定义 loss(商品token加权/难样本聚焦)**:官方明示了两个我们该用的手段——验证集监控(我们 recipe1 刚加上)+ 自定义 loss(可加权 itemic token)。
4. **官方明说过拟合诊断**:"eval_loss 明显高于 train_loss 且持续上升=过拟合,减轮次/加数据";"lr 过早归零→来不及收敛"——**这正是我们 v1 的病(lr 1epoch 归零)**,官方文档等于点名了我们的问题。
5. Transformers v5.3.0 建议(我们用 5.6,全参纯权重加载不受影响)。
